Icon Studio: A Skill That Builds Icon Libraries

Getting AI to produce consistent design output is a systems problem, not a prompting problem. I built the skill that encodes that system, then used it to make three icon sets in three very different styles.

Hero: the three sets side by side on one strip
Role
Solo
Timeline

Tools
Claude, Node + resvg, Figma, GitHub
Output
282 icons, 3 sets

TL;DR

I built icon-studio, a Claude skill that turns a style (rules or reference images) and an icon list into a consistent, production-ready icon set: hand-written SVGs, checked by script against a locked rules file, previewed on a fixed house-style page and exported as SVG + PNG. I then used it to make three sets in three very different styles.

The problem

A nice first icon, then a drifting set.

Asking an AI for “icons in this style” gets you a nice first icon and a drifting set. Each icon invents its own stroke, detail level, colours and size, so the family stops looking like one person drew it.

What I wanted instead

01

Consistency by construction

Every number (grid, stroke, palette, shape budget) lives in one file, and no icon gets an exception.

02

Verifiable output

Checks a script can run, not just “looks fine to me”.

03

Reusable across styles

The same process should work for a flat folk set and a sketchy line set.

04

Designer-ready delivery

Real SVGs I can copy into Figma, PNGs, and a page to review them on.

Building the skill

The rules are the product.

A set stays consistent because every decision is written down once and checked mechanically.

icon-studio workflow: two review gates

Gate A checks the four anchors against the references before anything else is drawn; Gate B repeats the checks for every batch.

Added after launch: 16 px variants

I noticed the skill never produced icons that held up at 16 px. The cause: icons were drawn once at 24 px and scaled down, so details blurred. I chose the proper fix over lowering the export size: a dedicated, hand-drawn 16 px version of every icon.

01

Separate small-size rules

A lighter 1 px stroke and a budget of 5 shapes, in their own block of the rules file (rule 13).

02

Redrawn, not scaled

Each 16 px icon is drawn fresh, then checked against its 24 px master.

03

New checks

The lint script checks the 16 px set too, and a pair sheet shows each 16 px icon beside its 24 px version.

04

Preview and Figma

A 24 px / 16 px switch in the sticky bar, and the two sizes become variants of one Figma component.

The three example sets were made before this update, so they ship at their main size only.

Three sets, three styles

Each set stress-tested a different part of the system.

The rule version history is the clearest record of what I caught and fixed.

Set 1 · 128 icons

Restaurant Folk Icons

Flat two-tone folk

Brief: Indian-folk menu icons (burgers, chai, biryani handi, utensils), palette sampled from a pink/red/orange cocktail-menu reference.

What changed

  • v1 → v2

    The first pass came out as spot illustration (19–31 shapes per icon, sparkles, shadows, tilt). I cut it to 12 shapes, two tones per part and no decoration, so it reads as icons.

  • v2.1

    Added translucent layering from the reference, capped at 3 overlaps and only on six named icons.

  • v2.2

    Every shade must start and end on the object's own edge or seam. Driven by a croissant that took three redraws before it read as five segments rather than overlapping blobs. This became a rule in the skill itself.

  • Bug

    The page script stripped width/height from inner rects, so the burger patty and cocktail stem vanished on the page and in copied SVG. Fixed in the skill's build script.

After v1 of this case study

  • 128 icons

    Scaled to 128 icons in 9 categories: Food, Drinks, Dietary tags, Service, Ordering and payment, Amenities, Info and contact, Staff and kitchen, Utility. Grouped by category on the page, never by drawing batch.

  • 3 fixes

    Three fixes from my review: the ice-cream cone's waffle lines stopped short, so they now run edge to edge; the tandoori chicken leg had no bone, so the meat shrank to reveal one; the smoothie's band and straw were misaligned with the tapered cup.

Set 2 · 90 icons

Travel Ink

Hand-drawn line

Brief: a full travel library, starting with luggage and documents, in the style of a bike illustration: dark grey ink with pop accents.

What changed

  • v1.1

    I spotted the passport was the only filled icon. It traced back to a one-off rule exception, so I removed the exception rather than patching the icon.

  • v2.0

    Added a hand-drawn line. Icons are drawn clean on the grid, then a script generates the sketched version, so the wobble is consistent and the source stays editable.

  • v2.1

    Dropped yellow; every icon must use both green and tangerine.

  • Flagged

    The striped duffel read as a basket; the boarding pass and ID card shared a silhouette.

After v1 of this case study

  • 90 icons

    Scaled from 10 to 90 icons in 9 categories: Luggage and documents, Transport, Navigation, Stay, Places and landmarks, Gear and essentials, Activities, Booking and money, Weather. All 80 new icons follow v2.1, with both accents in every icon.

  • Metaphors

    Hard metaphors under the rules: departure and arrival use a level plane with an up or down arrow, because the rules forbid rotation; delay became an hourglass so it doesn't clash with the clock; the waterfall took the most attempts.

Set 3 · 64 icons

Celestial Glass Icons

Gradients and grain

Brief: space icons from two references, a glass cocktail illustration and blue ceramics.

What changed

  • v2

    Stronger gradients, blended interiors, soft edges, glow on luminous objects, fractal grain, and a palette cut to brown and blue only.

  • v2.1

    Browns shifted golden.

  • Known limit

    Figma imports the blur but drops the grain, so the rules file says so.

After v1 of this case study

  • 64 icons

    Scaled from 17 to 64 icons in 7 categories: the original celestial bodies plus Spacecraft, Astronaut gear, Observation and science, Launch and mission, Life in space, Sci-fi and fun.

  • v2.2

    A scoped exception: simple eyes are allowed only on the alien, robot and space dog, because without them those icons didn't read. The no-faces rule stays for everything else.

  • Redraws

    From my review: space boots read as one boot, and re-entry read as a swing.

  • Bug

    Caught at scale: with 60+ icons on one page, gradient and clip-path ids collided and silently hid interior details. Fixed by giving each kind its own id prefix.

How I directed the AI

Five habits made it a system, not a one-off.

  1. Fix the rule, not the icon.

    When something looked wrong, I asked whether it was a one-off or a gap in the rules. The passport exception and the croissant both became rule changes that apply to every future set.

  2. Review rendered output, not code.

    I judged contact sheets, silhouettes and the live page. That is how I caught the missing burger patty, which no lint check would have found.

  3. Write taste down as constraints.

    “Fewest parts when unsure”, “no beige”, “group by category, never by batch” are subjective calls turned into checkable rules.

  4. Feed lessons back into the tool.

    Each set improved the skill: the layering rule, the fixed preview page, the rect bug fix and the “Copy all” for Figma all came from using it.

  5. Ship it as a product.

    I published the skill with a README, install steps, a licence and worked examples, and checked the public files for private details first, such as reference sources and my own feedback notes.

Outcome

282 icons across three styles, from one skill.

282 icons across three styles and 25 categories, all produced by the same skill. Per set, only the rules file and page config changed, plus one set-specific script (the sketch generator for Travel). The skill and all three libraries are public on GitHub, each library with its SVGs, rules file and a live preview page.
